# Журнал применения ИИ

Проект WiFiGuard, KIB-42 «Династия». Работа с OpenAI Codex, 21–22 ноября 2026 года. Ниже приведены реальные этапы и решения; это структурированная запись текущей сессии, не вымышленная история работы команды.

| Этап | Запрос или решение | Результат и проверка |
|---|---|---|
| Контекст | Пользователь сообщил о завершённых КТ1–3, передал реестр, методичку и тему; попросил подготовить КТ4 | Прочитаны Word и XLSM без изменения оригиналов. Найдена строка KIB-42 и заявленный формат MVP |
| Уточнение объёма | Предложены полный и базовый сценарии | Пользователь выбрал полный сценарий с помощником и повторной оценкой |
| Доставка и оформление | Уточнены запуск, публикация и стиль | Пользователь выбрал локальный запуск + ссылку, светлый сервис |
| ОС и доступ | Уточнены устройства и аудитория сайта | Пользователь выбрал Android, iPhone, Windows; открытая ссылка без входа |
| План | Подготовлены интерфейс, восемь факторов, критический минимум, тесты и комплект КТ4 | Пользователь дал команду: «Please implement the plan.» |
| Проверка источников | Прочитаны официальные рекомендации FTC, InfoSec и справки ОС | Принято: HTTPS защищает передачу и в открытой сети; VPN не устраняет фишинг. Отвергнута модель «публичный Wi-Fi всегда означает перехват всех данных» |
| Архитектура | Статический сайт без серверного хранения и вызовов ИИ | Принято: HTML/CSS/JS, Node.js для локальной раздачи, без пакетов для запуска |
| Расчёт | Реализованы чистая функция оценки, частичная неопределённость и критический минимум 75 | Проверены границы, округление, все 11 664 комбинации; безопасное изменение не повышает индекс |
| Помощник | Инструкции по ОС и подтверждение фактического ответа | Принято: пропуск сохраняет риск; отключение завершает оценку. Отвергнуто автоматическое снижение по нажатию «готово» |
| Верификация | Проверены сохранение, повреждённые данные и локальный сервер | 12 автоматических тестов проходят |
| Браузерная проверка | Встроенный браузер и Windows Computer Use оказались недоступны | Использован отдельный headless Chrome с Playwright, без доступа к пользовательскому профилю |
| Исправление интерфейса | Браузерная проверка выявила расширение главного блока на ширине 375 px | Исправлены минимальная ширина grid, расположение иллюстрации и перенос числовых вкладов факторов |
| Исправление теста | На мобильной ширине тест выбирал скрытую кнопку навигации | Селектор изменён на видимые элементы; логика приложения для этого не менялась |
| Документация | Подготовлены запуск, демонстрация, угрозы, тесты и ограничения | Описаны источники весов, самоотчёт и реальные границы прототипа |
| Дополнение macOS | Пользователь попросил добавить macOS к Android, iPhone и Windows | Добавлены отдельные инструкции по официальным справкам Apple, адаптирован выбор четырёх устройств, расширены проверки сохранения и браузерный сценарий |
| Идеи развития | Пользователь попросил сохранить обсуждённые функциональные расширения | В `docs/ROADMAP.md` зафиксированы шесть идей, ограничения и возможные интеграции; их реализация не начиналась |
| Новое задание | Пользователь попросил добавить проверку ссылки, историю оценок и печатный PDF без изменения расчёта | Добавлены `dist/src/portal.js`, `dist/src/history.js`, экраны и обработчики в `dist/src/app.js`, стили печати и тесты |
| Решения по безопасности | URL не открывается и не отправляется; официальные домены сравниваются только с самим доменом или его настоящими поддоменами; история сохраняется явно и без чувствительных данных | Ограничения и повреждённое хранилище обрабатываются локально; отсутствие Node/npm не позволяет заявить запуск тестов в текущей среде |
| Новая функция подключения | Пользователь попросил добавить проверку текущего подключения без расширений и локального приложения | Добавлены same-origin `/health`, измерение задержки, безопасное чтение Network Information API, два пользовательских вопроса и явные источники характеристик |
| Ограничения автоматического определения | Нельзя заявлять автоматическое определение SSID, WPA2/WPA3, сигнала или подлинности точки доступа | Интерфейс показывает недоступность данных и отдельно предупреждает, что скорость и задержка не являются доказательством безопасности |
| Публикация изменений 23 ноября | Пользователь попросил подтянуть два новых коммита из GitHub main и обновить прежнюю ссылку демо | Изменения получены fast-forward. Пройдены 19 тестов и браузерные проверки. Исправлены перенос кнопок на узких экранах и доступность `/health` на статическом хостинге |

Авторство реализации и текущих проверок — работа агента с ИИ под руководством пользователя. Реестр содержит роли участников, но не доказывает написание ими конкретных файлов. Личная проверка текста и кода всеми участниками в этой сессии не подтверждалась; такую проверку нельзя заявлять как выполненную.

Обзор аналогов, выводы о launch-площадках, презентация и видео текущей сессией не создавались. Предыдущие КТ приняты со слов пользователя, а незаполненные статусы копии реестра не исправлялись.
