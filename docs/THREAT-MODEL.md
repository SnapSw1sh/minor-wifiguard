# Модель угроз WiFiGuard, КТ4

Версия 1. Проверка реализации: 22 ноября 2026 года.

## Назначение и границы

Активы: понятность и корректность оценки, ответы в текущей вкладке, целостность статического приложения. Пользователь — посетитель общественного места или сотрудник организации. Набор данных состоит из перечислимых ответов, типа места, ОС и цели использования. Приложение не получает SSID, MAC/IP устройства из браузерных API, пароли, номера телефонов, файлы или трафик сети.

Границы доверия: браузер ↔ статический хостинг; JavaScript ↔ `sessionStorage`; рекомендации ↔ действия человека; внешние справки ↔ интерфейс. Настройками устройства управляет пользователь. Приложение не подтверждает реальное выполнение действия.

## Угрозы и меры

| Угроза / злоупотребление | Мера | Проверка / остаточный риск |
|---|---|---|
| Взломанный балл воспринимают как техническое заключение | В интерфейсе раскрыты происхождение балла, веса, ограничения и неизвестные ответы | Проверены подписи и методика. Ошибочные самоотчёты остаются возможны |
| Один опасный запрос маскируется безопасными ответами | Критический минимум 75 для портала и обхода ошибки сертификата | Тесты отдельных и совместных признаков |
| Пользователь отмечает запланированное действие как выполненное | Уточнение конкретного ответа, без автоматического уменьшения по чекбоксу; отдельное откладывание | UI-проверка пропуска и подтверждения. Честность самоотчёта не проверяется |
| Отключение от Wi-Fi показывается как «сеть безопасна» | Завершение оценки без нового балла; сохранение последнего результата | Сценарий 75 → завершение с последним индексом 75 |
| Изменение sessionStorage внедряет разметку или некорректное состояние | Белые списки значений, версия схемы, отбрасывание лишних полей, HTML-экранирование; безопасный сброс | Тесты повреждённого JSON, markup и неполных ответов |
| Утечка ответов через аналитику или внешние ресурсы | Нет внешних скриптов, шрифтов, API и аналитики; CSP разрешает только same-origin `connect-src 'self'` для проверки `/health` | В браузерном сценарии отслеживаются запросы. Хостинг видит технические данные HTTP |
| Вредоносный переход из внешней справки | Только фиксированные официальные URL, `noopener noreferrer` | Проверка исходников; содержимое внешних сайтов не контролируется |
| Локальный сервер раскрывает документы или принимает запись | Корень только `dist`; GET/HEAD; ограничения путей и типов; привязка 127.0.0.1 | Тесты traversal, POST, служебных файлов, некорректного URL |
| Пользователь теряет прогресс или хранилище заблокировано | sessionStorage с обработкой исключений; работа в памяти при отказе | Unit- и браузерные сценарии; после закрытия вкладки сохранение не гарантируется |
| Изменение опубликованных ресурсов посторонним | HTTPS-хостинг и управление исходниками владельцем проекта | Зависит от защиты аккаунта и платформы; CSP не заменяет доверие к хостингу |
| Проверка подключения создаёт ложное ощущение безопасности | Same-origin `/health` проверяет только доступность WiFiGuard; задержка и Network Information API явно описаны как технические характеристики | Низкая задержка и хорошая скорость не доказывают безопасность Wi-Fi, SSID, WPA или подлинность точки доступа |
| Браузер не поддерживает Network Information API | Проверка наличия API и нейтральное сообщение «Браузер не предоставляет эти данные» | Пользователь может указать защиту сети только по доверенным сведениям вручную |

## Безопасные ограничения

Никакого сканирования, перехвата, тестирования чужих систем, сбора учётных данных и обхода защит. Встроенные примеры синтетические. Учебный индекс не учитывает все классы атак и не проходил научную калибровку. Веса не выводятся из статистики отраслевых отчётов. Для рабочих данных правила организации имеют приоритет независимо от балла. Инструкции ОС зависят от версии и производителя; изменения выполняет сам пользователь. Проверка подключения делает только локальный same-origin запрос к служебному endpoint WiFiGuard.

При использовании сайта на заражённом устройстве, через вредоносное расширение или при компрометации самого хостинга конфиденциальность и целостность приложения не гарантируются. Прототип не предназначен для принятия решений о допуске к конфиденциальной корпоративной информации.
## Дополнение: проверка ссылок, история и печать

| Актив / угроза | Меры проекта | Ограничение |
|---|---|---|
| Пользователь открывает фишинговый URL из приложения | Используется только `URL`; URL не посещается, сетевые запросы к проверяемому адресу запрещены; CSP разрешает только same-origin `/health` | Анализирует структуру, но не содержимое, сертификат, репутацию или владельца сайта |
| Обманчивый адрес с `@`, IP, портом или похожим доменом | Показывается настоящий `hostname`, проверяются признаки и граница домена через точное имя или `.${domain}` | Признак не равен доказательству вредоносности; поддомен доверенного домена может быть скомпрометирован |
| IDN/Punycode ошибочно объявляется угрозой | Отдельное нейтральное пояснение о международном домене | Пользователь всё равно должен сверить написание с официальным источником |
| Утечка данных через историю | Явное сохранение; фиксированная схема и максимум 10 записей; URL, SSID и секреты не сохраняются; повреждённые записи отбрасываются | `localStorage` доступен странице и может быть очищен или прочитан другим скриптом того же origin |
| Ложное ощущение официального PDF | В отчёте явно указано, что это учебная оценка по ответам; экспорт — только печать | PDF не является доказательством безопасности сети или аудиторским документом |
| Проверка текущего подключения делает ложный вывод о безопасности | `/health` и задержка проверяют только доступность WiFiGuard; Network Information API отображается с источником данных | Скорость, задержка и тип соединения не подтверждают SSID, WPA2/WPA3, сигнал или владельца точки доступа |
