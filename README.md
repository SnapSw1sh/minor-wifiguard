# WiFiGuard

Учебный прототип команды **KIB-42 «Династия»**, КТ4, 23 ноября 2026 года.

Посетитель общественного места выбирает ситуацию, отвечает на восемь вопросов и получает объяснимый индекс риска 0–100. Помощник показывает рекомендации для Android, iPhone или Windows и пересчитывает индекс после подтверждённого пользователем изменения ответа.

**Демо:** https://wifiguard-kib42-dynasty.snapswish.chatgpt.site

## Локальный запуск

Нужен Node.js 20 или новее. Зависимостей, ключей и установки пакетов нет.

1. Распакуйте проект.
2. В Windows запустите `start.cmd` или выполните в папке проекта:

```powershell
node server.mjs
```

3. Откройте http://127.0.0.1:4173 в браузере. Для остановки нажмите Ctrl+C в окне сервера.

Если порт занят:

```powershell
$env:PORT = '4174'
node server.mjs
```

Откройте http://127.0.0.1:4174. Файл `index.html` нельзя запускать двойным щелчком: JavaScript-модулям нужен HTTP-сервер. Сервер слушает только локальный адрес, не открывая доступ ко всему компьютеру из сети.

## Что работает

- Пять общественных мест, три устройства, три цели использования.
- Опрос с пояснениями, вариантом «Не знаю» и возвратом к вопросам.
- Индекс, уровни риска, вклады факторов и критические предупреждения.
- Рекомендации, инструкции по ОС, откладывание действий без снижения балла.
- Уточнение фактических ответов, сравнение с исходной оценкой.
- Завершение после отключения от сети с сохранением последнего индекса.
- Три учебных примера, восстановление прогресса в текущей вкладке, полный сброс.
- Мобильная вёрстка, управление клавиатурой, методика и ссылки на источники.

## Как считается индекс

| Фактор | Вес |
|---|---:|
| Подлинность сети | 15 |
| Шифрование Wi-Fi | 10 |
| Страница подключения | 15 |
| Продолжение при ошибке сертификата | 20 |
| Использование HTTPS | 15 |
| Доверенный VPN | 5 |
| Обновления | 10 |
| Автоподключение | 10 |

Безопасный ответ даёт 0, неизвестный — половину веса, небезопасный — полный вес. Итог округляется один раз. Уровни: 0–24 низкий, 25–49 умеренный, 50–74 высокий, 75–100 критический.

Требование секретов от постороннего аккаунта, банковских реквизитов, установки неизвестного сертификата / профиля / приложения либо продолжение работы при ошибке сертификата задаёт минимум 75. Пока критический ответ сохраняется, включение VPN и другие улучшения этот минимум не отменяют.

Это **учебная эвристика команды**, а не вероятность взлома и не отраслевой стандарт. Публичная сеть не означает, что весь трафик открыт: HTTPS защищает соединение с сайтом. Сам HTTPS не доказывает честность сайта, а VPN не устраняет фишинг. Место не добавляет произвольные баллы. Цель использования уточняет рекомендации. Даже нулевой индекс не гарантирует безопасность.

## Демонстрация за 3–5 минут

1. Покажите выбор места, ОС и цели, затем первый вопрос и пояснение «Помогите разобраться».
2. Откройте «Учебные примеры» → «Кофе и рабочая встреча». Индекс — **43**, сумма до округления — 42,5.
3. В помощнике оставьте открытое шифрование без изменения. Уточните подлинность сети, обновления, автоподключение и доверенный VPN. При подтверждении этих условий результат станет **10**. На экране сохранится сравнение **43 → 10**.
4. Откройте пример аэропорта: индекс **75**, хотя округлённая сумма факторов — 38. Объясните критический минимум и завершите оценку через подтверждение отключения. Результат не превращается в 0.
5. Покажите пример торгового центра с индексом **0**, ограничения метода и первоисточники.

В учебных примерах изменяются только синтетические ответы. Нельзя выдавать показанные сценарии за сканирование реальной сети или реальные изменения настроек ОС.

## Проверки

```powershell
node --test
```

Тесты не требуют установки зависимостей. Они проверяют модель, все 11 664 комбинации ответов, сохранение состояния и локальный сервер. Протокол: [docs/TEST-REPORT.md](docs/TEST-REPORT.md).

Дополнительный сценарий `scripts/browser-check.mjs` требует Playwright и установленного Chrome/Chromium. Он проверяет интерфейс в отдельном тестовом профиле. Для системного runtime можно задать `PLAYWRIGHT_MODULE` (путь к `playwright/index.mjs`) и `CHROME_PATH` (путь к браузеру); `BASE_URL` по умолчанию равен http://127.0.0.1:4173. Скриншоты записываются в игнорируемую папку `artifacts`.

## Структура и программные интерфейсы

- `dist/` — весь публикуемый сайт, без сборки и внешних ресурсов.
- `dist/src/data.js` — вопросы, веса, примеры и источники.
- `evaluateAssessment(answers)` — чистая функция; возвращает `score`, `baseScore`, `level`, `factors`, `criticalSigns`, `unknownCount`, `floorApplied`. Неполные и неизвестные ответы отклоняются.
- `replaceAnswer(answers, id, value)` — создаёт новый набор ответов, не изменяя исходный.
- `getRecommendations(assessment, context)` — формирует упорядоченные действия и инструкции под ОС.
- `session.js` — проверка и хранение состояния; `app.js` — интерфейс.
- `server.mjs` — локальная статическая раздача; `test/` — автоматические проверки.
- `.openai/hosting.json` — привязка к опубликованному Sites-проекту.

Серверных API, базы данных, регистрации, аналитики и внешних вызовов ИИ нет. Ответы остаются в `sessionStorage` текущей вкладки. При блокировке хранилища опрос работает в памяти. В новой вкладке не обещается перенос прогресса. На хостинге могут сохраняться обычные технические сведения запроса, но приложение не отправляет ответы.

## Источники и обоснование

Рекомендации опираются на [FTC — Public Wi-Fi](https://consumer.ftc.gov/articles/are-public-wi-fi-networks-safe-what-you-need-know), [InfoSec — Tips on Using Public Wi-Fi](https://www.infosec.gov.hk/en/best-practices/person/tips-on-using-public-wi-fi), официальные справки [Apple](https://support.apple.com/102480), [Google](https://support.google.com/android/answer/9075847?hl=ru) и [Microsoft](https://support.microsoft.com/en-us/windows/experience/connectivity-networking/essential-network-settings-and-tasks-in-windows). Они подтверждают меры защиты, но не численные веса нашей модели.

Связь с банком знаний команды: SRC-239, отчёт Solar JSOC о кибератаках 2025 года; SRC-386, Cisco Talos IR Trends Q2 2026. Эти материалы дают общий контекст угроз и кибергигиены. Их статистика не используется как частота атак именно через публичный Wi-Fi. Для утверждений непосредственно о Wi-Fi используются профильные источники выше.

Исследование продуктовых аналогов и launch-площадок не входило в реализацию КТ4; соответствующие выводы не выдумывались. До финальной сдачи нужно приложить фактический ресеч команды, презентацию и видео/очную защиту по методичке.
