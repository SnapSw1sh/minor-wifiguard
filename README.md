# WiFiGuard — оценка рисков публичного Wi-Fi (KIB-42)

Веб-приложение для оценки условий использования публичного Wi-Fi: проверка доступности подключения, разбор ссылки на страницу входа, интерактивная оценка риска и персональные рекомендации. Результат можно сохранить в истории браузера или в PDF.

Учебный проект по дисциплине «Безопасность предпринимательской деятельности», раздел «Кибербезопасность», Блок 2. Версия для КТ4 — 23 ноября 2026 года.

## Проблема и пользователь

При подключении к сети в кафе, метро, торговом центре, аэропорту или на вокзале пользователю приходится оценивать несколько разных условий: подлинность сети, запросы страницы входа, защиту передачи данных и настройки устройства. При этом хорошая скорость и знакомое название сети сами по себе не подтверждают безопасность.

**Пользователь:** посетитель общественного места или сотрудник организации, использующий публичный Wi-Fi со смартфона или ноутбука.

**Гипотеза:** объединение доступных технических сведений, разбора URL и пошаговых рекомендаций поможет пользователю замечать подозрительные признаки и выбирать меры защиты. Прототип проверен на синтетических сценариях; влияние на поведение реальных пользователей не измерялось.

## Возможности приложения

### Проверка текущего подключения

Раздел «Моё подключение» проверяет доступность самого WiFiGuard запросом к `/health` и показывает приблизительное время ответа. При поддержке браузером Network Information API также отображаются тип соединения, оценка его скорости и задержки, режим экономии данных.

У каждого показателя указан источник: «Определено автоматически» или «Указано пользователем». Если браузер не предоставляет характеристику, приложение сообщает об этом. Указанный вручную тип защиты сети подставляется в опрос, а ответ о работе с корпоративными данными уточняет цель использования.

Проверка не определяет SSID, WPA2/WPA3, мощность сигнала или владельца точки доступа автоматически. Показатели скорости и доступности не входят в индекс риска.

### Опрос и персональный план защиты

Пользователь выбирает место, устройство и цель использования, затем отвечает на восемь вопросов. Приложение рассчитывает индекс 0–100, объясняет вклад каждого ответа и формирует план действий.

Поддерживаются **Android, iPhone, Windows и macOS**. Помощник содержит инструкции по настройкам выбранной ОС. После уточнения ответов результат пересчитывается и сравнивается с исходным. Действие можно отложить без снижения индекса; подтверждение отключения от сети завершает оценку с сохранением последнего балла.

Вопросы допускают ответ «Не знаю», возврат и продолжение после обновления страницы. Для знакомства с приложением доступны три подготовленных примера.

### Проверка ссылки на страницу входа

Инструмент разбирает URL прямо в браузере, не открывая указанный сайт. Он показывает настоящий хост и отмечает:

- HTTP или HTTPS;
- данные пользователя перед символом `@`;
- IP-адрес вместо домена и нестандартный порт;
- признаки международного домена — IDN/Punycode;
- совпадение с официальным доменом, если он указан пользователем.

Принимаются ссылки с `http://` или `https://`. Официальный домен задаётся без пути, порта и учётных данных. Проверяется точное совпадение или настоящий поддомен: `login.example.test` соответствует `example.test`, а `example.test.other.test` — нет.

Это анализ структуры адреса. Репутация сайта, его содержимое, сертификат и принадлежность организации не проверяются. HTTP, IP-адрес, необычный порт или IDN сами по себе не доказывают вредоносность. Результат этого инструмента автоматически не меняет балл опроса.

### История проверок

Кнопка «Сохранить результат» добавляет оценку в локальную историю. Хранятся до **10 последних записей**: дата, место, устройство, цель использования, индекс и уровень риска.

История сохраняется между посещениями в этом браузере. Доступны удаление отдельных записей и полная очистка. Ответы опроса, проверенные URL, SSID и секреты в историю не записываются.

### Отчёт в PDF

На странице результата кнопка «Сохранить отчёт PDF» открывает стандартное окно печати. Через пункт «Сохранить как PDF» можно получить отчёт с датой, индексом, уровнем риска, основными факторами и рекомендациями.

Печатная версия скрывает навигацию и кнопки. Генерация отчёта не требует отправки результатов на сервер.

## Как рассчитывается индекс риска

Индекс основан на ответах пользователя. Автоматические характеристики соединения и результаты разбора URL показываются отдельно.

| Фактор | Максимальный вклад |
|---|---:|
| Подлинность выбранной сети | 15 |
| Шифрование Wi-Fi | 10 |
| Требования страницы подключения | 15 |
| Продолжение работы при ошибке сертификата | 20 |
| Использование HTTPS | 15 |
| Доверенный VPN | 5 |
| Обновления системы и браузера | 10 |
| Автоматическое подключение к сети | 10 |

Безопасный ответ даёт 0, «Не знаю» — половину веса, небезопасный — полный вес. Сумма округляется до целого один раз.

**Уровни:** 0–24 — низкий риск, 25–49 — умеренный, 50–74 — высокий, 75–100 — критический.

**Критический минимум — 75 баллов:** применяется, если портал запрашивает секреты от другого аккаунта, банковские реквизиты или установку неизвестного сертификата, профиля либо приложения, а также при продолжении работы вопреки ошибке сертификата. Другие улучшения не отменяют этот минимум, пока критический ответ сохраняется.

Веса и границы выбраны для учебной модели. Они не определяют вероятность взлома и не выведены из статистики отраслевых отчётов. Тип места не добавляет баллы; устройство и цель использования уточняют рекомендации.

## Данные и безопасность

| Данные | Где и как используются |
|---|---|
| Ответы текущего опроса и его контекст | `sessionStorage` текущей вкладки; новая оценка очищает этот прогресс |
| Сохранённые результаты | `localStorage`, до 10 записей после явного сохранения; новая оценка не удаляет историю |
| URL и официальный домен | Разбираются в браузере, не отправляются на проверяемый сайт и не сохраняются в истории |
| Отчёт | Формируется из текущего результата и сохраняется средствами печати браузера |

При недоступности хранилищ опрос работает в памяти страницы, а история может быть недоступна. Хранилище браузера также может быть очищено его настройками.

Проверка подключения обращается только к адресу самого WiFiGuard. Ответы опроса и проверяемые ссылки не передаются серверу. Регистрации и аналитики приложения нет; хостинг может обрабатывать обычные технические сведения HTTP-запроса.

Пароли, SMS-коды, банковские реквизиты и файлы не нужны. Встроенные примеры вымышленные. Сканирование сетей, перехват трафика и проверки чужих систем не выполняются. Выводимые значения экранируются, сохранённые данные проверяются, сетевые обращения ограничены политикой CSP.

Подробности: [модель угроз](docs/THREAT-MODEL.md).

## Как запустить

Доступно [онлайн-демо](https://wifiguard-kib42-dynasty.snapswish.chatgpt.site). Для локального запуска нужен **Node.js 20 или новее**. Установка пакетов, сборка и API-ключи не требуются.

```powershell
git clone https://github.com/SnapSw1sh/minor-wifiguard.git
cd minor-wifiguard
node server.mjs
```

Откройте **http://127.0.0.1:4173**. В Windows вместо команды запуска можно открыть `start.cmd`. Для остановки сервера — Ctrl+C.

JavaScript-модулям нужен HTTP-сервер, поэтому запуск `dist/index.html` двойным щелчком не поддерживается. Локальный сервер слушает только адрес этого компьютера. При занятом порте перед запуском можно задать другой: `$env:PORT = '4174'`.

## Ограничения и развитие

- Индекс основан на самоотчёте и учебных весах. Даже 0 баллов не гарантируют безопасность сети.
- HTTPS защищает передачу, но не доказывает честность сайта. VPN не устраняет фишинг или ошибки сертификатов.
- Поддержка Network Information API зависит от браузера; отображаемая оценка скорости не является полноценным тестом пропускной способности.
- Настройки устройства приложение не меняет. Инструкции зависят от версии ОС и производителя; Safari, Firefox, физические смартфоны и компьютеры Mac отдельно не тестировались.
- История остаётся в одном браузере и не синхронизируется между устройствами. PDF содержит учебную оценку, а не аудиторское заключение.
- Для рабочих данных действуют правила организации независимо от балла.

Дальнейшие направления — пользовательское тестирование, уточнение модели, карта мест с Wi-Fi, интеграция баз репутации URL и расширенное сравнение подключений. Обсуждённые идеи сохранены в [списке развития](docs/ROADMAP.md).
